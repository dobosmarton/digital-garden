I'm on the subway. I pull out my phone, open Telegram, and type:

> "Create a task about integrating web search as an agent tool"

Within seconds, the bot responds with a structured task: title, acceptance criteria, technical considerations, all enriched from my one-line prompt. An agent picks it up and starts exploring the codebase. Ten minutes later, a plan appears in my chat:

> "Agent completed..."

I read it on my phone. The approach is mostly right, but I want it simpler. I reply:

> "Explore other providers, create a decision matrix and conclude to one."

The plan updates. I check it again and it looks good. I type:

> "Approved, go ahead with implementation."

I put the phone away. By the time I get home, there's a PR waiting for review.

## The problem: dead time and context fragmentation

I juggle 3-4 side projects in parallel. Each lives in its own repo, has its own backlog, and needs regular attention.

The problem is the gaps between coding sessions: the 20-minute commute, the 10-minute wait for coffee, the walk to the grocery store. These fragments add up to 1-2 hours per day that is completely dead for engineering work.

And then there's the idea problem. Sometimes I get ideas during commutes, before this system, those ideas went into a notes app. Then I'd forget about them or just needed extra effort to write a proper task based on half formed idea.

I wanted a system where those fragments of time move projects forward, with me still making the decisions from wherever I happen to be. And I wanted ideas to go straight from my head to the backlog with zero middle steps.

## No laptop required

Now the entire system runs on a cheap VPS. The Telegram bot, the task board and the agent runner are all Dockerized and run 24/7 on the server.

I don't need to keep my laptop open, or I don't need to buy an expensive Mac Mini. I don't need to SSH into anything to kick off work.

If I have an idea for a feature at 11pm, I can create the task and let the agent explore the codebase and draft a plan overnight. When I wake up, the plan is waiting for my review in Telegram. No code gets written until I approve it.

## The Telegram bot

The bot is backed by a [Mastra](https://mastra.ai) AI agent with Plane API tools. You send natural language messages, and the agent figures out what you mean and calls the right API.

Here's what actual interactions look like:

**Creating a task:**

> "Add a task about caching the server responses for the API project"

The bot responds with a formatted task including title, description, acceptance criteria, and technical considerations, based on what I asked for and the project's context.

**Reviewing a plan:**

> "What's the plan for XY task?"

The bot pulls up the agent's proposed approach: which files it wants to change, the implementation strategy, and any concerns it flagged. I read it on my phone and decide whether it makes sense.

**Refining the plan:**

> "Update the plan — don't refactor the auth module, just add the endpoint directly"

I can change the agent's approach from my phone before any code gets written.

**Approving implementation:**

> "Looks good, go ahead"

Only now does the agent start writing code. Every plan needs my approval before implementation begins.

**Checking what needs my attention:**

> "What tasks are in Plan Review?"

The bot returns the tasks where agents have finished planning and are waiting for my review, so I can go through them on the phone right away.

**Capturing an idea on the go:**

> "Add to the backlog: the mobile app should support offline mode for saved items"

The idea goes straight to the project backlog, enriched with context, acceptance criteria, and technical considerations. No notes app, no "I'll add this later."

**Checking agent status:**

> "What's the agent queue status?"

The bot returns a summary: which agents are running, what they're working on, how much they've spent today, and what's queued up next.

## Task enrichment

The bot also expands what I write before it goes to the task board. When I say "add rate limiting," it generates:

- a clear title under 80 characters
- a description that expands on my intent with context
- acceptance criteria: concrete, testable conditions for "done"
- technical considerations: edge cases, dependencies, potential pitfalls
- an out of scope section when relevant

This comes from explicit guidelines in the system prompt:

```
## Task Creation Guidelines
When the user asks you to create a task:
1. Identify which project it belongs to. If ambiguous, ask which project.
2. Craft a clear, concise title (imperative mood, under 80 chars).
3. Write a detailed description_html with sections:
   - Description: Expand on the user's intent. Add context and clarity.
   - Acceptance Criteria: Bullet list of concrete, testable conditions.
   - Technical Considerations: Implementation notes, edge cases, dependencies.
   - Out of Scope: Anything explicitly not covered, if relevant.
4. Proactively add details the user might not have mentioned — gaps,
   edge cases, things to consider. This is your key value: enriching
   brief requests into well-structured, thorough task descriptions.
```

The enrichment feeds directly into the planning phase. A vague "add rate limiting" task leads to a vague plan that I'd have to rewrite anyway. With acceptance criteria in the task, both the agent and I know what "done" means from the start.

## The review loop from your pocket

The workflow has five steps:

1. The agent plans. After I create a task, the agent explores the codebase in read-only mode and proposes an approach. It posts the plan as a comment on the task and moves it to "Plan Review." Nothing gets implemented until I say so.
2. I review on my phone. The plan shows up in Telegram. I read it while waiting for coffee. Does the approach make sense? Is it changing too much? Is it missing an edge case? I can see all of this in a chat message.
3. I refine or approve. If the plan needs adjustment, I reply with feedback, for example "use the existing middleware instead of writing a new one" or "skip the migration, just add the column." The agent incorporates my feedback. If the plan looks good, I approve and the agent moves to implementation.
4. The agent implements. Now the agent writes code, runs tests, and creates a PR. If it hits a question mid-implementation ("should this error return 400 or 422?"), it asks via Telegram. I reply from my phone and the agent resumes.
5. I review the PR. The task moves to "In Review." I usually do this on my laptop, but everything before this step happened on my phone.

## What this actually feels like

A typical session looks like this:

1. Open Telegram and check what's in "Plan Review" across projects
2. Read a plan for the API project and approve it
3. Read a plan for the mobile app and reply with "use the existing component, don't create a new one"
4. An idea hits me ("the game tool should support replay analysis"), I tell the bot, and it lands in Backlog
5. Promote yesterday's backlog idea to Todo, so the agent starts planning it
6. Answer an agent question about error handling
7. Check queue status: 2 agents running, 1 queued, $8.40 spent today

By the time I sit down at a laptop, there are PRs waiting for review, fresh ideas captured in backlogs, and a kanban board that tells me where everything stands across all my projects.

I still review the PRs on the laptop. But the agent never writes code without my approval on the plan, and because the plans come to my phone, I can approve them from anywhere. That changes how many projects I can realistically keep moving.
